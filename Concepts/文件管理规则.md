# 新资料的放置与命名

仅约定以后新建的资料，不要求搬迁或重命名旧文件。当前整个论文目录保持原样，论文实验管理等汇报后另行讨论。

## 放置

| 新内容 | 位置与要求 |
| --- | --- |
| AI、编程、数学、电路课程笔记 | 原领域下的课程目录；按原课次或章节组织 |
| 新论文 | 当前不调整论文目录；解除限制后再沿用对应主题和论文索引 |
| 新实验 | 本轮不创建、搬迁或整理；不进入公开同步清单 |
| 课程专属代码练习 | 对应课程内，标明教材、第三方改编或个人实现 |
| 独立算法题练习 | [Practice](../Practice/README.md) 对应题库；提交前确认操作的是哪一个 Git 仓库 |
| 数学推导 | 单一课程或论文专属内容留在原笔记；跨主题概念用本目录添加链接 |
| 课程图片、讲义与附件 | 对应课程内，保留来源和现有引用习惯；不要统一搬到根附件目录 |
| 临时草稿 | 已知主题则放主题内；未知主题则放 [Inbox](../Inbox/README.md) |
| 暂未分类下载 | Inbox；整理时确认来源、用途和公开范围，不自动上传 |

## 命名

- 课程笔记沿用“课次或章节 + 标题”；中文、空格和现有编号习惯继续保留。
- 论文使用稳定标题，年份、作者和来源放在索引或属性中；本轮不重命名现有论文。
- 将来新建实验如获授权，可用“日期_方法_数据集_用途”；避免 `final2`、`latest-new` 等含义不稳定的名称。
- 同名笔记优先用目录、完整路径和 Aliases 消歧，不为形式统一批量加前缀。
- 新文件补一个稳定导航入口即可；不要为同一进度建立多份人工维护表。

## 两套导航

- 已有 README 的个人学习目录保留 `README.md` 供 GitHub 使用；同层按课程或主题命名、以“导航.md”结尾的文件供 Obsidian 使用（例如“人工智能导航.md”“动手学深度学习导航.md”），不统一命名或添加“00”，留在本地并由 Git 忽略。
- 在 Obsidian 中使用本地导航的 Wiki 链接；在公开 README 中使用指向其他 README 或资料的 Markdown 相对链接，不指向本地专用导航。
- 新资料需要入口时，只更新受影响的两套导航，保持内容事实、学习状态和来源一致；不另外维护重复的进度表。
- Obsidian 排除并隐藏 README，但文件仍保留。实验目录、第三方源码和本地维护工具沿用既有边界，不据此批量创建导航或上传资料。

## 本地与公开范围

原创普通笔记和导航可按明确清单同步。私人草稿、账号配置、学校内部资料及来源或分发范围不明的附件，不因放入某个目录而自动适合公开。权重、数据和实验内容不进入本轮同步。

只暂存明确列出的文件，先检查暂存差异，再提交。不要使用 `git add .`，不要把主仓库干净解释为嵌套仓库也干净。Practice 目前保留两套既有历史，不执行自动整合或删除内部 Git 目录。
