## 题目描述

本题要求编写程序，计算序列 $2/1 + 3/2 + 5/3 + 8/5 + \dots$ 的前 $N$ 项之和。

注意该序列从第 2 项起，每一项的分子是前一项分子与分母的和，分母是前一项的分子。

### 输入格式

输入在一行中给出一个正整数 $N$。

### 输出格式

在一行中输出部分和的值，精确到小数点后 2 位。题目保证计算结果不超过双精度范围。

### 输入样例

```text
20
```

### 输出样例

```text
32.66
```

---

## 解题思路与核心知识点

1. **递推关系**：设第 $k$ 项为 $a_k / b_k$，初始设“第 0 项” $a_0 = 1, b_0 = 1$，则每轮迭代：
   $$c = a,\quad a \leftarrow a + b,\quad b \leftarrow c$$
   第 1 轮恰好得到 $2/1$，第 2 轮得到 $3/2$，第 3 轮得到 $5/3$，以此类推，循环 $N$ 次累加 `a / b` 即可。
2. **为什么要使用 `double` 存储分子与分母**：斐波那契数列呈指数增长（$F_{47}$ 即超过 32 位 `int` 上限），用 `double` 存储分子分母既能自然得到浮点商，又可在 $N$ 较大时不触发整型溢出。

> [!warning] 原源码两处关键 Bug 复盘
> 原始 `5-0.c` 在不同编译器或平台上可能输出错误结果甚至 `0.00`，原因有二：
> 1. **格式符与变量类型不匹配（未定义行为）**：源码将 `N` 声明为 `double`，却写作 `scanf("%d", &N);`——`%d` 只往 8 字节 `double` 地址写入 4 字节整数位模式，读出的双精度值几乎为 `0`，导致循环根本不执行或异常！**修正**：将 `N` 和计数 `i` 声明为 `int`。
> 2. **局部变量未初始化**：`double sum;` 未赋初值 `0.0`，在栈区残留随机垃圾值，累加结果不可控。**修正**：改为 `double sum = 0.0;`。

## 完整源码

```c
/*
本题要求编写程序,计算序列 2/1+3/2+5/3+8/5+... 的前N项之和。
注意该序列从第2项起，每一项的分子是前一项分子与分母的和，分母是前一项的分子。
输入格式：   输入在一行中给出一个正整数N。
输出格式：   在一行中输出部分和的值，精确到小数点后2位。题目保证计算结果不超过双精度 范围。
输入样例：   20
输出样例：   32.66
*/
#include <stdio.h>
int main(){
    double N,a=1,i;
    double sum,b=1.0,c;
    scanf("%d",&N);
    for (i=1;i<=N;i++){
        c=a;
        a+=b;
        b=c;
        double fact=a/b;
        sum+=fact;
    }
    printf("%.2lf",sum);
    return 0;
}
```
